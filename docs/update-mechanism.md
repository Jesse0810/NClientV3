# 检查更新与预览版

启动检查和设置中的“检查更新”使用同一逻辑，读取 `Jesse0810/NClientV3` 的公开 Releases。默认只检查正式版；“包含预览版更新”开启后，正式版和预览版共同参与比较。设置页和启动时读取的默认值均为关闭，保留用户已经保存的选择。

## 版本与构建标识

- 识别正式标签 `vX.Y.Z`、预览标签 `vX.Y.Z-zh-preview.N`，兼容 `preN`／`rcN` 的版本比较。
- 先比较主、次、补丁版本，再比较预览阶段和数字编号。例如 `4.2.15-zh-preview.10` 高于 `.2`，`4.2.15` 正式版高于该版本的所有预览版，旧补丁版本不会因发布时间更晚而成为更新。
- 不依赖 GitHub 列表顺序。每页读取 100 条并跟随分页选择最高版本，最多 20 页；HTTP 错误、JSON 错误或超过分页上限均报检查失败，不把未完成的检查显示成“没有更新”。
- 发布工作流传入 `-PreleaseTag=vX.Y.Z[-zh-preview.N]`。Gradle 校验标签的基础版本与源码版本一致，将完整标签写入 `BuildConfig.RELEASE_TAG`，并把预览编号写入版本名。例如 `4.2.15-zh-preview.2-debug`。
- 已发布的旧正式版从 `4.2.14-release` 等版本名回退识别；未包含编号的旧 Debug 版本视为该基础版本的未知旧预览。它们无法补出已经遗漏的历史编号，新构建使用完整标识避免重复提醒同一预览。

## 安装包选择与切换

仅选择本仓库、所选标签下名称和下载 URL 一致、状态为 `uploaded` 且大小有效的 APK。支持当前 `android9plus`／`android8`、预览版 `_debug.apk` 及旧正式版 `_pre28.apk` 命名；排除未签名 APK、校验文件、错误版本、错误来源及缺少匹配系统 APK 的版本。

如果同一预览提供同包名及独立 Debug 包，优先选择与当前应用包名一致的包。浏览器按钮总是打开所选版本的发布页，预览版不会被导向正式版 Latest。

正式版包名为 `com.maxwai.nclientv3`，当前 Debug 预览包名为 `com.maxwai.nclientv3.debug`。两者可并存，切换时展示独立安装和导出／导入说明，操作按钮打开对应发布页。API Key 与漫画图片需要另行配置或迁移。

## 下载与安装

同包名更新下载到应用私有缓存，无需旧版外部存储权限，也不再依赖 `downloaded` 偏好值或跨实例静态待下载版本。每个请求直接保留完整的版本和 APK 信息。

下载检查 HTTP 状态、发布大小、完整长度及 GitHub 提供的 SHA-256（若有）；完整下载后读取 APK 实际包名、版本、versionCode 和签名。Android 8 使用签名兼容 API，Android 9+ 使用 SigningInfo。下载内容无效、版本不符、降级或传输中断均不启动安装。签名不同则提示先在应用目录之外备份数据与漫画，再查看发布页手动处理。

临时文件只有在检查通过后才成为最终缓存 APK，失败会清理。安装和提示在主线程运行；后台自动检查失败不弹出错误提示，手动检查会反馈错误。

## 验证

`python3 scripts/check_release_updates.py` 使用实际 `UpdateRelease`、`ReleaseFeed` 和 `UpdateApkValidator` Java 代码。Android JSON token 与 PackageManager 使用测试适配器，不依赖联网或设备。回归包含公开 Release 元数据快照、预览开关、正式版晋升、多位预览编号、乱序及跨页选择、错误附件、空说明、下载长度／摘要和不同系统的签名／包名／版本检查。

JSON token 适配器不替代 Android 原生 JSON 词法分析或 PackageManager 对真实 APK 的验签；APK 构建、元数据检查与上述逻辑测试分别执行，不能作为真机安装测试的声明。
