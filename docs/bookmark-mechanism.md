# 加入书签机制排查

排查基线：`278e8b6`（4.2.9 书签编辑测试版）。

## 原来的行为

“加入书签”保存当前请求快照，包括完整原始查询、全站或在线收藏范围、排序、页码和名称。它不是把当前漫画列表复制到一个收藏夹；打开时会重新请求符合条件的结果。

- `MainActivity` 同时承载首页、搜索、标签结果及在线收藏，并共用 `res/menu/main.xml`。书签项原先默认可见，主页面没有按场景限制显示。
- `BookmarkDialogs.showAdd` 原先只检查查询是否可以恢复；空查询也合法。因此无筛选首页及在线收藏列表都能保存。
- `FavoriteActivity` 承载本地“收藏漫画”，基线代码已明确隐藏书签项，也没有新增书签的点击处理。已离线核对公开发布的 4.2.9 Android 9+ APK，其 DEX 中同样包含该隐藏逻辑；这不等于设备运行验证，用户报告仍需结合实际安装包和页面确认。
- 新建路径只有 `MainActivity → BookmarkDialogs → Queries.BookmarkTable`。`SearchActivity` 的保存路径用于编辑已有书签。

## 本次收紧

菜单默认隐藏，主页面根据 `InspectorV3.canAddBookmark()` 显式启用；新增对话框使用相同规则再次校验。
切换语言筛选或从管理标签返回后，会重新计算入口是否显示。
从书签打开的结果页隐藏搜索按钮及“加入书签”。通过入口标记判断，因此内部恢复为搜索、标签或收藏查询时仍适用。

| 场景 | 能否新增 |
| --- | --- |
| 全站结果有关键词 | 可以 |
| 全站结果有包含或排除标签 | 可以 |
| 全站结果有页数或上传时间范围 | 可以 |
| 管理标签或语言设置实际应用了筛选的首页 | 可以 |
| 无筛选首页 | 不可以 |
| 只切换排序或页码 | 不可以 |
| 在线收藏，包括在收藏中搜索 | 不可以 |
| 本地收藏、单本漫画、随机漫画 | 不可以 |

不能只看请求是不是搜索：无筛选的热门排序会用 `-nclientv3` 作为内部占位查询，切回最新排序后该占位也可能保留。本次判断不把它视为用户筛选条件。

已有书签不删除；旧的在线收藏类或空条件书签仍可打开、改名，或补充筛选条件。

## 在管理页新增及取消分页保存

- “管理书签”右上角新增“＋”，打开“新增书签”表单，可以直接设置名称、关键词、包含/排除标签、上传时间范围、排序，不必先运行搜索。
- 新建和编辑书签不再提供“页面范围”输入。已有书签中保存的页数条件保持兼容，普通高级搜索页仍可配置该项。
- 新表单初始为空，范围固定为全站，不自动带入全局语言、标签或在线黑名单。名称及实际筛选条件均为必填，只有名称或排序时无法新建。
- 全站是默认搜索行为，不再显示不可选择的“搜索范围：全站”说明，编辑表单、条件弹窗及加入书签摘要均适用。历史在线收藏书签仍显示其实际范围，继续按原范围查询。
- 新增及编辑共用表单，草稿可在界面重建时恢复；取消不会写入数据库。
- 书签不再记录结果列表的浏览页码。新旧书签均从第一页打开，列表不显示页码，改名也不会恢复旧页码。漫画的页数范围仍然属于筛选条件。
- 新保存的 URL 移除结果分页参数，查重也忽略该参数，因此从不同结果页保存不会重复新增同一 URL 条件组合。
- 为兼容旧备份，保留旧数据库 `page` 列，新写入恒为 1，读取时不使用。旧 URL 仍用于定位原记录，不自动合并或删除不同名称的历史书签。

## 两行列表与条件弹窗

- 列表仅显示单行名称和“查看条件”，移除省略的条件摘要。编辑、删除按钮横排，避免竖排按钮撑高卡片。
- “查看条件”使用详情页的字段行布局，按原作、角色、内容标签、画师、社团、语言、类别分组；关键词、排序和保存的范围条件也分别显示，仅历史收藏范围需要额外标明。
- 包含值使用勾号及绿色背景，排除值使用叉号及红色背景，适配浅色和深色主题。可见文字只显示值，读屏描述仍说明包含/排除关系。
- 长值完整换行，弹窗可滚动，不把完整条件省略。所有值只读，仍沿用现有标签译名及内容标签可见清单的翻译规则。
- 复杂表达式整条展示，保留 OR、NOT、括号及负号，仅翻译可识别的标签值并用中性背景突出，避免颜色错误暗示全局包含/排除关系。
- 该展示层不修改原始查询、书签数据或标签偏好。

- 提取实际 Inspector 构造、查询、翻页、排序及可新增判断方法进行 JVM 验证，1180 条断言通过，覆盖两个 SDK 分支和五种排序；依赖的 Android、数据库和全局设置使用轻量桩。
- 实际书签模型及保存/查重方法通过 327 条 JVM 断言，覆盖分页参数移除、编码保留、旧记录定位、跨页查重和兼容列写入；URI、数据库和 Inspector 依赖使用轻量桩。
- 实际编辑表单方法通过 156 条 JVM 断言，覆盖直接新增、必填校验、取消、草稿恢复及旧书签编辑；另通过 12 条入口和资源接线检查。界面及状态依赖使用轻量桩。
- 条件弹窗的实际展示及格式化方法通过 126 条 JVM 断言，覆盖字段分组、正负值、译名、范围、旧记录及复杂表达式；两行列表接线与浅深色配色检查通过。Android 渲染、资源访问和书签模型依赖使用轻量桩。
- 现有书签数据库迁移、重命名、冲突保护及 63 条查询/范围检查通过。
- Android 9+、Android 8 两个 Debug APK 编译通过。
- 当前没有连接 Android 设备，未验证手机上的菜单显示。
