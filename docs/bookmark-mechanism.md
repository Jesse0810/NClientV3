# 加入书签机制排查

排查基线：`278e8b6`（4.2.9 书签编辑测试版）。

## 原来的行为

“加入书签”保存当前请求快照，包括完整原始查询、全站或在线收藏范围、排序、页码和名称。它不是把当前漫画列表复制到一个收藏夹；打开时会重新请求符合条件的结果。

- `MainActivity` 同时承载首页、搜索、标签结果及在线收藏，并共用 `res/menu/main.xml`。书签项原先默认可见，主页面没有按场景限制显示。
- `BookmarkDialogs.showAdd` 原先只检查查询是否可以恢复；空查询也合法。因此无筛选首页及在线收藏列表都能保存。
- `FavoriteActivity` 承载本地“收藏漫画”，基线代码已明确隐藏书签项，也没有新增书签的点击处理。已离线核对公开发布的 4.2.9 Android 9+ APK，其 DEX 中同样包含该隐藏逻辑；这不等于设备运行验证，用户报告仍需结合实际安装包和页面确认。
- 新建路径只有 `MainActivity → BookmarkDialogs → Queries.BookmarkTable`。`SearchActivity` 的保存路径用于编辑已有书签。

## 本次收紧

菜单默认隐藏，主页面根据 `InspectorV3.canAddBookmark()` 显式启用；新增对话框使用相同规则再次校验。
切换语言筛选或从管理标签返回后，会重新计算入口是否显示。
从书签打开的结果页隐藏搜索按钮及“加入书签”。通过入口标记判断，因此内部恢复为搜索、标签或收藏查询时仍适用。

| 场景 | 能否新增 |
| --- | --- |
| 全站结果有关键词 | 可以 |
| 全站结果有包含或排除标签 | 可以 |
| 全站结果有页数或上传时间范围 | 可以 |
| 管理标签或语言设置实际应用了筛选的首页 | 可以 |
| 无筛选首页 | 不可以 |
| 只切换排序或页码 | 不可以 |
| 在线收藏，包括在收藏中搜索 | 不可以 |
| 本地收藏、单本漫画、随机漫画 | 不可以 |

不能只看请求是不是搜索：无筛选的热门排序会用 `-nclientv3` 作为内部占位查询，切回最新排序后该占位也可能保留。本次判断不把它视为用户筛选条件。

已有书签不删除；旧的在线收藏类或空条件书签仍可打开、改名，或补充筛选条件。

## 在管理页新增及临时浏览设置

- “管理书签”右上角新增“＋”，打开“新增书签”表单，可以直接设置名称、关键词、包含/排除标签、上传时间范围，不必先运行搜索。
- 新建和编辑书签不再提供“页面范围”输入。已有书签中保存的页数条件保持兼容，普通高级搜索页仍可配置该项。
- 新表单初始为空，范围固定为全站，不自动带入全局语言、标签或在线黑名单。名称及实际筛选条件均为必填，只有名称时无法新建。
- 全站是默认搜索行为，不再显示不可选择的“搜索范围：全站”说明，编辑表单、条件弹窗及加入书签摘要均适用。历史在线收藏书签仍显示其实际范围，继续按原范围查询。
- 新增及编辑共用表单，草稿可在界面重建时恢复；取消不会写入数据库。
- 书签不再记录结果列表的浏览页码和排序。新旧书签均从第一页、按最新排序打开，改名也不会恢复旧浏览设置。漫画的页数范围仍然属于筛选条件。
- 新建、编辑、条件弹窗及添加摘要不提供或展示书签排序。结果页仍可临时调整排序，只修改当前 Inspector，不写回书签或全局排序偏好；菜单显示当前实际排序。
- 新保存的 URL 移除结果分页和排序参数，查重也忽略这两个参数，因此不会因所在页或排序不同而重复新增同一 URL 条件组合。查询值中的同名文字及原有编码保持原样。
- 为兼容旧备份，保留旧数据库 `page` 列，新写入恒为 1，读取时不使用。旧 URL 仍用于定位原记录，旧排序参数不再生效，不自动合并或删除不同名称的历史书签。

## 紧凑列表与条件弹窗

- 列表左侧仅显示单行名称，右侧将“查看条件”、编辑、删除归为同一组并横排、垂直居中，移除省略的条件摘要。
- “查看条件”使用详情页的字段行布局，按原作、角色、内容标签、画师、社团、语言、类别分组；关键词和保存的范围条件也分别显示，仅历史收藏范围需要额外标明。
- 包含值使用勾号及绿色背景，排除值使用叉号及红色背景，适配浅色和深色主题。可见文字只显示值，读屏描述仍说明包含/排除关系。
- 长值完整换行，弹窗可滚动，不把完整条件省略。所有值只读，仍沿用现有标签译名及内容标签可见清单的翻译规则。
- 复杂表达式整条展示，保留 OR、NOT、括号及负号，仅翻译可识别的标签值并用中性背景突出，避免颜色错误暗示全局包含/排除关系。
- 该展示层不修改原始查询、书签数据或标签偏好。

## 搜索页直接显示条件

- 普通搜索页进入后直接显示完整筛选条件，移除顶部展开/收起条件的“＋”开关。
- 搜索框固定在顶部，提示“输入搜索关键字（可选）”；下方筛选表单和历史记录统一滚动，保证末尾字段也可访问。各分类添加标签的“＋”保留。
- 底部固定“搜索”按钮，与键盘搜索共用提交逻辑。关键字可留空，直接按标签／范围条件查询；未更改条件时继续沿用原有偏好，无条件时显示默认结果。只有非空关键字写入搜索历史。
- 内容标签不再预填热门推荐项；已有包含／排除偏好、在线黑名单及旧书签条件继续显示。添加内容标签时默认设为“包含”，已有的排除选择保留。设置页同时移除不再生效的热门标签数量选项。
- 书签编辑仍使用独立的“保存书签”按钮，名称、条件和保存行为保持不变。
- 类别源数据有两条 `misc`（ID `97152`、`153091`），它们都翻译为“其他”且生成同一筛选条件。表单按原始类型和名称合并重复选项，保留非默认选择状态，数据库原始 ID 和漫画关联不改动。
- 已选类别和语言统一在固定选项处显示，避免再次添加为可关闭的重复项；不同类型同名或不同原名同译名的值仍分别保留。

## 内容标签、原作、角色、画师和社团选择

- 五个字段不再预先填入热门推荐标签，只展示实际已选的条件；已有标签偏好、在线黑名单和旧书签中的条件继续保留。类别及语言选项保持原有规则。
- 点击字段的“添加”后打开可搜索下拉框，异步读取该字段的已有值，不受管理标签的最低出现次数设置限制。内容标签的 1127 个批准原值保留，7 组拼写／同义别名合并后默认显示 1118 个概念；其他四字段保留全部已有值。输入关键词只用于筛选，必须点选一个已有选项才能确认，键盘提交使用同样的校验，不再将手输译文创建为临时内容标签。
- 内容标签逐项区分语义，例如 `group` 显示“群交”、`orgy` 显示“乱交聚会”。拼写别名在主选择器、管理列表和详情合并展示，点击“查询旧拼写”可单独选择旧原值；同一概念的标准写法与旧拼写在筛选表单中互相替换。旧书签的明确旧拼写查询保留，筛选条件中显示旧拼写提示。
- 原作、角色、画师、社团仍仅给同字段重名项附加“（原文）”。选项按显示名称排序，可搜索显示名称及原始名称，长下拉选项可换行。完整排查见[重名清单](../data/translation-collisions/README.md)，内容标签的逐项决定见[语义复核](../data/tag-translations/content-label-review/README.md)。
- 简体中文界面通过四字段离线名称表显示原作／角色的简中名及画师／社团的日文原名。欧美、混源或未确认的项仍保留原文，具体范围及逐项来源见[四字段名称清单](../data/entity-translations/README.md)。
- 添加时核对数据库中的 ID、类型及原名，使用原始值生成筛选条件，不把译名存成查询值，也不新增任意名称的标签。新选择默认“包含”，已存在的选择不重复添加，原有排除状态保留。
- 新建及编辑书签共用上述选择方式；旧书签中已保存、当前数据库缺失的值仍按原有恢复方式展示，避免编辑时丢失条件。
- 网站不支持已测试的 OR 合并搜索。按用户选择，标准项搜索规范原值，旧拼写入口搜索选中的旧值；排除合并概念时提交各成员的负条件。新书签保存可编辑的逻辑条件，执行时才展开排除项，不将展开后的重复别名写回书签。
- 标签下拉在输入 1 个字符后即触发，按显示名／原值的任意位置匹配，例如“群”可以匹配“群交”。普通搜索、书签新增／编辑和旧拼写入口共用同一选择器，并显式设置单字符阈值；4.2.13 的旧内容标签输入框未设置该值，继承了系统默认的 2 字符阈值。

## 验证

- 搜索提交与内容标签添加方法通过 653 条 JVM 断言，覆盖空关键字、范围条件、原始标签值、包含／排除状态、历史记录和书签模式隔离；Android 控件与数据库使用轻量桩。新增固定搜索按钮及关键字提示后的两个 Debug 版本均编译通过，尚未在真机上验证布局。
- 四字段选择方法通过全量库存回归，覆盖推荐移除、全部已有值、ID/类型/原名校验、选中状态、旧书签恢复和原始查询值；另有 34 项实际下拉与弹窗方法检查，覆盖关键词搜索、同译名不同原值、确认及键盘提交校验、取消和加载失败。Android 控件、事件和数据库使用轻量桩，未验证真机下拉渲染及平台 Filter 并发时序。
- 固定选项去重后的实际表单方法通过 3787 条 JVM 断言，覆盖真实类别/语言清单、六个唯一类别、偏好合并、书签恢复及原始 ID 保留；界面和数据库使用轻量桩。
- 取消排序保存后，实际书签模型/保存与查重方法通过 452 条 JVM 断言，实际 Main 排序方法通过 2501 条断言；覆盖旧记录身份、默认最新排序、跨排序查重、结果页临时排序及全局设置隔离。Android URI、数据库、对话框和 Inspector 使用轻量桩。
- 提取实际 Inspector 构造、查询、翻页、排序及可新增判断方法进行 JVM 验证，1180 条断言通过，覆盖两个 SDK 分支和五种排序；依赖的 Android、数据库和全局设置使用轻量桩。
- 实际书签模型及保存/查重方法通过 327 条 JVM 断言，覆盖分页参数移除、编码保留、旧记录定位、跨页查重和兼容列写入；URI、数据库和 Inspector 依赖使用轻量桩。
- 实际编辑表单方法通过 156 条 JVM 断言，覆盖直接新增、必填校验、取消、草稿恢复及旧书签编辑；另通过 12 条入口和资源接线检查。界面及状态依赖使用轻量桩。
- 条件弹窗的实际展示及格式化方法通过 126 条 JVM 断言，覆盖字段分组、正负值、译名、范围、旧记录及复杂表达式；两行列表接线与浅深色配色检查通过。Android 渲染、资源访问和书签模型依赖使用轻量桩。
- 现有书签数据库迁移、重命名、冲突保护及 63 条查询/范围检查通过。
- Android 9+、Android 8 两个 Debug APK 编译通过。
- 当前没有连接 Android 设备，未验证手机上的菜单显示。
