# 清除标签偏好修复记录

排查基线：`3344cd4`，已发布的 4.2.10 测试版。

## 原因及历史

`TagTypePage.reset()` 存在两处旧缺陷：

- “已应用筛选”页调用数据库清除，但随后仅通知适配器重绑旧 Cursor，未重新查询。列表和勾选图标仍可能显示旧状态。
- 内容标签、画师、角色、原作、社团页只启动标签数据更新，没有执行清除。该更新流程原本还会保存偏好，更新后再恢复，因此不能用于清除偏好。

这段 `reset()` 在上游基线 `8877d12` 与 4.2.10 中相同。分类分支可追溯到 `28b7acef`，旧 Cursor 的刷新方式可追溯到 `66681dc7`；最近的汉化、搜索及书签改动没有修改该方法。

## 修复行为

- “已应用筛选”清除所有本地包含/排除状态；具体分类页按类型清除。清除不受搜索词、最小出现次数或内容标签可见清单限制。
- 清除后重新执行当前搜索，刷新当前页及其他已创建的标签页。标签条目保留，状态恢复为默认。
- 确认框说明清除范围。“在线黑名单”属于账户数据，隐藏本地偏好清除入口。
- 标签元数据更新只更新名称、分类和计数，保留现有偏好与在线标记；移除下载前保存偏好、完成后恢复旧快照的步骤，避免覆盖更新期间的清除操作。
- 不修改已保存书签中的筛选条件。

## 验证范围

- 212 条 JVM 断言通过：执行实际页面清除、重新筛选和确认框方法；同一测试重现旧实现的两个故障。Android 界面、Filter 和数据库使用轻量桩，未验证真实异步 Filter。
- 291 条数据库断言通过：实际 Java 方法输出数据库操作，再回放到真实 SQLite；覆盖分类/全量清除、隐藏及低数量标签、元数据刷新顺序、在线标记及漫画关联保留，并重现旧快照回写问题。
- 现有 63 条书签查询/范围检查及数据库兼容检查通过。
- Android 9+、Android 8 两个 Debug APK 构建通过。

当前没有连接 Android 设备，尚未进行手机界面验证。
